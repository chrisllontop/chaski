## The chaski object

`createChaski()` returns the in-process API: your Worker calls it directly, with no HTTP in between.
[ChaskiEntrypoint](/docs/other-workers) serves the same calls to your other Workers.

| Call | Returns | |
| --- | --- | --- |
| `ready()` | `{ channels, paused, dryRun, environment, templates }` | Checks the config and the applied migrations, lists the [paused](/docs/dashboard#pause-a-channel) channels, names the `environment` the config gives (`null` without one) and counts the templates, changing nothing; throws the `config` error a send would. |
| `send(request)` | `SendResult` | Sends now; see [Sending](/docs/sending). |
| `schedule(request)` | `ScheduleResult` | Sends at `scheduledAt`; see [Scheduling](/docs/scheduling). |
| `schedules.list({ recipientId? })` | `ScheduledItem[]` | Pending schedules, soonest first. |
| `schedules.cancel(query)` | `{ cancelled }` | Cancels by `id`, `idempotencyKey` or `groupKey`. |
| `feed.list(query)` | `FeedPage` | A recipient’s feed, newest first, a page at a time. |
| `feed.unreadCount(recipientId)` | `{ unread }` | |
| `feed.markRead(input)` | `{ marked }` | Marks `ids`, everything `before` an instant, or the whole feed. |
| `preferences.get(recipientId)` | `ChaskiPreferences` | |
| `preferences.set(recipientId, update)` | `ChaskiPreferences` | Merges channels; `mutedTypes` overwrites the list. |
| `preferences.topics()` | `{ topic, types }[]` | Template types grouped by topic. |
| `push.register(request)` | `{ id }` | Registers a web push subscription or an iOS device token. |
| `push.unregister(query)` | `{ unregistered }` | By `recipientId`, `endpoint` or `deviceToken`. |
| `push.vapidPublicKey()` | `{ publicKey }` | The key for `pushManager.subscribe()`, or `null`. |
| `templates.import(file, { preview? })` | `TemplateImportResult` | Creates or updates templates by type from a [template file](/docs/templates#keep-templates-in-a-file); `preview` only reports. |
| `templates.export()` | `TemplateFile` | Every template, as the file `templates.import()` takes. |

`ready()` suits a health route: it asks the database each time, so a database that doesn’t answer
fails it too. `templates` counts the templates outside the trash; at `0`, every send is refused as
an unknown type, as on a fresh database or after a deploy that forgot to load them. `paused` names
the channels someone [paused](/docs/dashboard#pause-a-channel) in the dashboard, whose deliveries
wait as held.

```ts
app.get('/health', async (c) => {
  try {
    const status = await chaski.ready();
    return c.json({ chaski: status }, status.templates > 0 ? 200 : 503);
  } catch (error) {
    return c.json({ chaski: String(error) }, 503);
  }
});
```

It also mounts and consumes:

| Call | |
| --- | --- |
| `routes(options)` | The dashboard, its API and the open-tracking pixel, as a Hono app to mount. |
| `userRoutes(options)` | The signed-in user’s feed, devices and preferences, as a Hono app to mount. |
| `queue(batch, env, ctx)` | Handles a batch from Chaski’s queue and returns `true`; leaves any other batch untouched and returns `false`. |

## Requests

```ts
type SendRequest = {
  type: string;
  recipient: Recipient;
  payload?: Record<string, unknown>;
  channels?: Array<'email' | 'in_app' | 'push'>;
  transactional?: boolean;
  email?: { fromName?: string; replyTo?: string; attachments?: AttachmentInput[] };
  idempotencyKey?: string;
  // Delivers the one transactional email before send() returns; see Sending.
  inline?: boolean;
};

type ScheduleRequest = Omit<SendRequest, 'inline'> & {
  // ISO 8601 with an explicit offset: Z or ±hh:mm.
  scheduledAt: string;
  groupKey?: string;
};

type Recipient = {
  id: string;
  email?: string;
  name?: string;
  phone?: string;
  timezone?: string;
  locale?: string;
};

type AttachmentInput = {
  filename: string;
  contentType: string;
  // Exactly one of content (base64) or url.
  content?: string;
  url?: string;
  disposition?: 'attachment' | 'inline';
  contentId?: string;
};
```

## Feed items

```ts
type FeedItem = {
  id: string;
  type: string;
  title: string;
  body: string;
  href?: string;
  readAt: string | null;
  createdAt: string;
};

type FeedPage = { items: FeedItem[]; nextCursor: string | null };
```

`feed.list()` takes a `recipientId`, and optionally a `cursor` from the last page, a `limit` up to
100 and `unreadOnly`.

## User routes

`chaski.userRoutes()` answers these paths, relative to where you mount it, for the user `identify`
returns. `chaskijs/client` calls them for you.

| Method and path | |
| --- | --- |
| `GET /feed` | The feed; `cursor`, `limit` and `unreadOnly` as query parameters. |
| `GET /feed/unread-count` | `{ unread }` |
| `POST /feed/read` | Marks items read: `{ ids?, before? }`, or `{}` for the whole feed. |
| `GET /feed/socket` | A WebSocket that announces new items, and reads made in other tabs and devices. |
| `GET /preferences` | The user’s preferences. |
| `PATCH /preferences` | Updates them. |
| `GET /preferences/topics` | Template types grouped by topic. |
| `GET /push/vapid-public-key` | `{ publicKey }` |
| `POST /push/subscriptions` | Registers this browser’s subscription, or an iOS device token. |
| `DELETE /push/subscriptions` | Drops one, by `endpoint` or `deviceToken`. |

A path the mount doesn’t serve, including those of a group left out of `groups`, reaches your
app’s own 404, and `identify` doesn’t run for it. So a second mount can sit under the first
one’s path (`/me/notifications/team` under `/me/notifications`) and both answer, in whichever
order you register them. The dashboard’s mount is the exception: it’s a single-page app, so it
answers every path under its own.

Writes and socket upgrades from an origin other than the request’s own, `publicUrl`’s or one in
`allowedOrigins` answer 403. Errors answer as `{ error, message }`, with the codes in
[Errors](/docs/errors).
