## createChaski()

Call it once, in your Worker’s main module. It takes a function of the Worker’s `env` that returns
the config, and Chaski runs that function on every call: secrets and vars always come from the env
of the moment.

```ts
import { createChaski } from 'chaskijs';

export const chaski = createChaski((env: Env) => ({
  publicUrl: env.CHASKI_PUBLIC_URL,
  bindings: { db: env.CHASKI_DB, queue: env.CHASKI_QUEUE },
}));
```

Chaski checks the config on every call, and a mistake throws a `config` error that starts with
`Chaski config:` and names the option, such as
`Chaski config: channels.email is configured but bindings.email is missing`.

## ChaskiConfig

| Option | Type | |
| --- | --- | --- |
| `publicUrl` | `string` | Required. The absolute http(s) URL where you mount `chaski.routes()`. |
| `bindings` | `ChaskiBindings` | Required. The resources Chaski runs on; see below. |
| `channels` | `object` | The channels to turn on. A channel is on when it has an entry. |
| `defaultMutedTypes` | `string[]` | Types every contact has muted until they save preferences of their own. |
| `environment` | `string` | Where the Worker runs, such as `production`, shown in the dashboard and returned by `ready()`. `local` opens the dashboard without `authorize` and needs a `publicUrl` on localhost; see [Local development](/docs/local-development#open-the-local-dashboard). Unrelated to `channels.push.apns.environment`, which picks the APNs server. |
| `maxRetries` | `number` | Must match `max_retries` on your queue consumer. Defaults to `5`. |
| `migrationsTable` | `string` | Must match `migrations_table` on your D1 binding. Defaults to `d1_migrations`. |
| `onError` | `(error, context) => void` | Receives every unexpected error Chaski handles on its own. |

## bindings

| Key | Binding | |
| --- | --- | --- |
| `db` | D1 database | Required. Where Chaski keeps its data. |
| `queue` | Queue producer | Required. Every delivery goes through it. |
| `email` | `send_email` | Required by `channels.email`. |
| `feed` | `ChaskiFeed` Durable Object | Required by `channels.in_app`. |
| `scheduler` | `ChaskiScheduler` Workflow | Required by `chaski.schedule()`. |
| `events` | `ChaskiEvents` Durable Object | Live updates in the dashboard. |
| `attachments` | R2 bucket | Required by sends that carry email attachments. |

## channels

### email

| Option | |
| --- | --- |
| `from` | Required. The sender address; the `send_email` binding must allow it. |
| `fromName` | The sender’s display name. |
| `replyTo` | The address replies go to. |

### in_app

No options yet: `in_app: {}` turns the channel on.

### push

Configure `vapid` for web push, `apns` for iOS, or both.

| `vapid` | |
| --- | --- |
| `subject` | A `mailto:` or `https:` contact the push services can reach you at. |
| `publicKey` | The base64url uncompressed P-256 public key (65 bytes), as web-push tools print it. |
| `privateKey` | The base64url P-256 private key (32 bytes), or the whole private JWK as JSON. |

| `apns` | |
| --- | --- |
| `teamId` | Your Apple team id. |
| `keyId` | The APNs key’s id. |
| `bundleId` | Your app’s bundle id. |
| `environment` | `'sandbox'` or `'production'`. |
| `privateKey` | The contents of the `.p8` file. |

## onError

`onError` receives the errors Chaski handles itself, such as a failed delivery in the queue or a
request that answered 500, with where it happened:

```ts
onError: (error, context) => {
  // context.source: 'http' | 'queue' | 'workflow' | 'tracking' | 'feed' | 'events'
  // and, when they apply: deliveryId, notificationId, scheduledId, channel
  console.error('chaski', context, error);
},
```

## routes()

| Option | |
| --- | --- |
| `dashboard.authorize` | Required. Decides who gets into the dashboard; see [Dashboard and sign-in](/docs/dashboard). |
| `dashboard.canPauseChannels` | `(c, actor) => boolean`. Who may pause a channel and send or discard what it holds; without it, nobody can, except in the `local` environment. See [Pause a channel](/docs/dashboard#pause-a-channel). |

## userRoutes()

| Option | |
| --- | --- |
| `identify` | Required. Returns the signed-in user’s id, `null` to answer 401, or a `Response`. |
| `allowedOrigins` | Origins of your frontend when it’s served from another origin than these routes. Your app answers CORS for them: see [Browser clients](/docs/browser-clients). |
| `groups` | The routes the mount serves: `['feed', 'push', 'preferences']` by default. A team inbox `identify` names `team:<id>` serves `['feed']`: a browser belongs to one contact, so registering it there would take it from the user’s own inbox. Leave out `preferences` when your app keeps a preferences API of its own, so the browser can’t write around its rules. |
| `allowPush` | `(c, recipientId) => boolean`, asked before a device is registered; `false` answers 403. Removing a device is always allowed. |

Mount `userRoutes()` once per inbox: each mount’s `identify` names its contact, with a feed, a
socket and an unread count of its own.
