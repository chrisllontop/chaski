## Mount the dashboard

`chaski.routes()` mounts the dashboard, its API and the email open-tracking pixel on any path of
your app. The dashboard ships built inside the package, so there is nothing to upload or host:

```ts title="src/index.ts"
app.route(
  '/admin/notifications',
  chaski.routes({
    dashboard: { authorize: cloudflareAccess({ teamDomain, audience }) },
  }),
);
```

Set `publicUrl` in the config to the absolute URL of that mount, such as
`https://app.example.com/admin/notifications`.

## Choose who signs in

`authorize` runs before every page and API call of the dashboard. It returns who is signed in, as
`{ id, name? }`, `null` to answer 403, or a `Response` such as a redirect to your login page:

```ts
type Authorize = (c: Context) => Actor | null | Response | Promise<Actor | null | Response>;
type Actor = { id: string; name?: string };
```

Admin actions, such as a replay or a template change, are recorded under the `id` it returns.
Chaski ships two:

- `cloudflareAccess({ teamDomain, audience })` checks the token of a
  [Cloudflare Access](https://developers.cloudflare.com/cloudflare-one/applications/) application
  that protects the mount path: its signature against your team’s keys, the application’s AUD tag,
  the issuer and the expiry. The signed-in email becomes the actor.
- `basicAuth({ username, password })` asks the browser for one username and password, compared in
  constant time; read them from secrets.

Your own sign-in works the same way: return the user it finds, or `null`. Under `wrangler dev`,
`environment: 'local'` in the config opens the dashboard without `authorize`; see
[Local development](/docs/local-development#open-the-local-dashboard).

```ts
authorize: async (c) => {
  const user = await currentStaffUser(c);
  return user ? { id: user.email, name: user.name } : null;
},
```

## What it shows

- **Overview**: notifications, sent, success rate and open rate for a period, deliveries per day,
  delivery latency and the health of each type on each channel.
- **Deliveries**: every delivery and its status, with each attempt’s error, a replay for the
  failed and dead ones, and the held ones a paused channel keeps.
- **Schedules**: pending scheduled sends, which you can cancel. One still pending a minute after
  its time shows as overdue.
- **Templates**: the editor, with a live preview and a test send for email.
- **Channels**: what Chaski picked up from your config, and a pause for each channel.

## Pause a channel

**Pause** on the **Channels** page is the emergency brake: a provider failing, a bug sending the
same push again and again, content that went out wrong. From then on every delivery of that
channel waits as **held** instead of going out, transactional and scheduled ones included, and
the header shows the channel as paused. The pause lives in Chaski’s database, so it stays until
someone resumes the channel, deploys included.

**Resume** asks what to do with what the pause held: send it all now, or keep it. Kept deliveries
stay under the **Held** tab of **Deliveries**, where you send or discard each one, or every one of
a channel and type. A delivery sends only once its channel runs again, and a discarded one shows as
skipped and never goes out. An [inline send](/docs/sending#inline) on a paused channel throws
`channel_paused`, and its email waits as held like the rest.

Pausing stops password resets along with everything else, so it takes a permission of its own.
Give `routes()` a `canPauseChannels` check; without it nobody can pause, or send or discard what a
pause holds, except in the `local` environment, where pausing only holds this machine’s email:

```ts
const dashboard = chaski.routes({
  dashboard: {
    authorize: cloudflareAccess({ teamDomain, audience }),
    canPauseChannels: (c, actor) => OPS_TEAM.includes(actor.id),
  },
});
```

`chaski.ready()` lists the paused channels under `paused`, for a health check that should notice.

## Live updates

With the `ChaskiEvents` Durable Object bound as `events`, open dashboards refresh as deliveries
change, and the header says **Live**. Without it, the dashboard still works, and refreshes when you
come back to its tab or reload it.
